Product-Market Fit Canvas

TLDR: Stack the five layers of product-market fit, from target customer at the bottom to user experience at the top, and check that every layer is held up by the one below it. Reach for it after you have a value proposition and before anyone writes a feature list.

The full idea

You have a job statement, two personas, and a value proposition for the lunch gap. Each of those answers one question well. This guide stacks them into one picture so you can see whether they hold each other up. The tool is Dan Olsen's Product-Market Fit Pyramid, from The Lean Product Playbook. Olsen's point is that product-market fit is not a feeling you get later. It is five specific layers, and fit means each layer actually rests on the one under it.

Bottom to top the layers are: target customer, underserved needs, value proposition, feature set, and user experience. A line runs across the middle. The bottom two layers are the market, and you do not control them. You can only understand them, choose them, or choose wrong. The top three are the product, and those you build. That line is the whole reason the model is useful: most teams argue about the top three while the answer is sitting in the bottom two.

The connecting move is value mapping. You take each underserved need and ask which part of your offer serves it. Then you take each feature and ask which need it answers. No feature is allowed to exist without a need above it in the pyramid, because a feature with no need behind it is a guess that costs money. This is the same fit check you did on the Value Proposition Canvas, now applied to the whole stack instead of one exchange.

Olsen wraps the pyramid in a six step Lean Product Process: determine your target customer, identify their underserved needs, define your value proposition, specify your minimum viable product feature set, create the MVP prototype, then test it with customers. The rhythm to remember is that you build the pyramid bottom up and you test it top down. You reason from customer to needs to value to features. But a customer can only ever touch the user experience, so feedback arrives at the top and travels down. When someone hates the prototype, the fault may be the screen, or the feature set, or the value proposition, or you may have picked the wrong customer entirely. Test top down means asking those questions in order instead of redesigning the button.

For the lunch gap, the honest version might be: target customer is the desk-bound office worker on a fixed break, not everyone who eats lunch. The underserved need is arrival time you can trust inside a 60 minute window, which nobody serves well today. The value proposition answers that need. The feature set is only what delivers that promise. The most common mistake is skipping straight to the feature set and calling the rest obvious. As a product manager, this one page is what lets you say no to a good idea, out loud, because it has no need above it.

Build it step by step

STEP 1

What is the Product-Market Fit Pyramid?

15 min
Search

Then explain the six steps of the Lean Product Process, and what it means to build the pyramid bottom up but test it top down. Use a delivery marketplace at lunchtime as the example.

The five layers in order, the market and product line across the middle, the six steps of the Lean Product Process, and the reason feedback always enters at the top layer even when the fault is lower down.
Build
Draw the empty five layer pyramid in your doc for the lunch gap. Then place what you already own: the two personas from Personas and Archetypes go beside the target customer layer, the job statement from JTBD Framing and your ranked pains go beside underserved needs, and the value proposition statements from Value Proposition Canvas and Statements go beside the value proposition layer. Leave feature set and user experience empty.
Capture
Write one sentence that starts "The bottom two layers are the market, which means ...".
STEP 2

Lock the two market layers

25 min
Search
Here are my two personas and my ranked pains and gains for the weekday lunch gap: [paste]. Help me write the bottom two layers of the Product-Market Fit Pyramid. First a target customer that is specific enough to exclude people, not a demographic. Then a list of underserved needs, each one rated on how important it is and how well it is served today. Tell me which needs are genuinely underserved and which ones are already well served by what people do now.
Get
One named target customer with the people it deliberately leaves out, and a needs list rated on importance and current satisfaction, where underserved means high importance and low satisfaction.
Build
Pick one primary target customer for this round and write down which persona you are not serving first and why. Then cut every need that scored high on satisfaction, however real it is. A need already met by the office microwave is not your opening.
Capture
Write your primary target customer and your top three underserved needs into your doc, each need with the evidence line from your interviews that supports it.
STEP 3

Map value from needs to features

25 min
Search
Here are my target customer, my three underserved needs, and my value proposition statement for the lunch gap: [paste]. Do a value mapping pass. For each underserved need, name the part of the value proposition that serves it and then the smallest feature set that delivers it. Then go the other way: for each feature, name the need above it. Show me any feature with no need behind it and any need with no feature under it.
Get
A two way map: needs pointing down to features, features pointing up to needs, with the orphans on both sides named out loud.
Build
Delete every feature with no need above it, even the one you like most. For every need left with no feature under it, either write a feature or write "not served in this round" beside it. Then check that the value proposition layer still says the same thing your statements said, and fix whichever one drifted.
Capture
Write your value mapping rule in one sentence. A stem: "A feature stays in the pyramid only when ...".
STEP 4

Add the user experience layer

20 min
Search
Here is my feature set for the lunch gap and the needs each feature serves: [paste]. Sketch the user experience layer in words: the few screens or moments where the target customer meets these features between 11:00 and 12:30 on a workday. For each moment, tell me which feature it makes visible and which underserved need the person is feeling at that moment.
Get
A short walk through the lunch moment where each screen traces to a feature and each feature traces to a need, so the top layer is not decoration.
Build
Write the walk as five or six lines in your doc, starting at the moment hunger and the calendar collide. Mark any moment where the person has to trust something they cannot see yet. Those are the moments the experience layer has to carry on its own.
Capture
Write one sentence that starts "The experience layer is where the customer touches the pyramid, so ...".
STEP 5

Test it top down

20 min
Search
Play my target customer for the lunch gap: [paste the persona]. Stay in character. I am going to describe the lunch experience I sketched, layer by layer, and I want your honest reaction as this person. Then step out of character and tell me, for each negative reaction, which pyramid layer it points at: the experience, the feature set, the value proposition, the underserved need, or the target customer itself.
Get
Reactions from the top layer plus a read on which layer each complaint really comes from. You have no lunch customers on hand, so Claude simulates one and you label it that way in your notes: a first draft, never proof.
Build
Repeat with the second persona in a fresh conversation. Then find the lowest layer any complaint pointed at and fix that layer first, because everything above it inherits the problem. If a complaint reached the target customer layer, say so plainly in your doc rather than moving a button.
Capture
Write the finished pyramid into your doc with all five layers filled. Add one sentence that starts "I build bottom up but test top down because ...". This pyramid feeds the Lean Canvas next, and the feature set feeds the Kano Model later.

Make it a skill

Your doc now holds a five layer pyramid for the lunch gap, a target customer with the people it excludes, three underserved needs with evidence, a value map with the orphans removed, and your rule for reading feedback down the stack.

Turn this into a Claude skill file called SKILL.md named pmf-canvas. Keep my words and my examples. Add the frontmatter with a name and a description that says when to use it. Do not add rules I did not write.

Then test it: paste your second persona and its pains into a fresh chat and prompt "use my pmf-canvas skill to build the pyramid for this segment and tell me which features have no need above them".

Smells to watch for

  • A feature set filled in first, with the bottom layers written afterwards to justify it.
  • A target customer so wide it excludes nobody. That is a market, not a target.
  • Needs listed without an importance and satisfaction rating, so nothing is actually underserved.
  • Features with no need above them, kept because someone senior likes them.
  • Every piece of negative feedback treated as a design problem, so no fix ever reaches a lower layer.
